## Implementation Integrity Verdict

**Pass with a known gap.** The cashier flow expresses one product-specific system: gold-paper ground, white slips with brass edges, one red rate stamp, three type sizes, one money column, Thai-first labels from one string table, one `Dialog` behind every modal, and one server that re-derives every amount from the locked rate. `impeccable detect` over `src` is clean (0 findings, exit 0). The only drift is on the manager editor: every label, button, field hint, empty state, confirmation, and pagination control is hard-coded English. PRODUCT.md says Thai-first with English alongside on every screen; the editor is the one surface that does not honour that.

## Executive Summary

- Audit Health Score: **16/20** (Good)
- Issues: P0 0 · P1 1 · P2 3 · P3 7
- Top issues:
  1. **[P1] Manager editor is English-only.** Every label and field on `/editor` (and its overlays) bypasses `src/lib/i18n.ts`. Thai counter staff and Thai managers will see an English-only back office. Native-speaker review is the blocker on adding Thai strings, but the gap is real and the audit must call it out.
  2. **[P2] Stale rate can be locked silently.** `PaymentCalculation.handleLock` does not check `rate.stale`. If the network has been down for several minutes and the last cached rate is older than `STALE_AFTER_MS` (5 min), the cashier can lock it and take money at a price the shop can no longer defend.
  3. **[P2] `setSearchParams({ page: '1' })` after `addItem` wipes the manager's active filter.** The object form of `setSearchParams` replaces, it does not merge. A manager who has filtered to a category and added a new piece loses the filter and has to re-pick the category from the rail.
  4. **[P2] Editor's first load fetches the full inventory and filters / paginates in the browser.** `editorMenu` calls `getInventory()` with no params, then runs the `search` / `categories` filter and pagination client-side. Fine at 13 seeded pieces; a real shop's hundreds of items will be a one-time stall on every editor open.
- Next: `/impeccable clarify` (Thai strings for the editor — needs the native-speaker loop the existing copy is waiting on), `/impeccable harden` (stale-rate lock guard, keep-filter on add), `/impeccable adapt` (the phone receipt footer is fixed; nothing new), `/impeccable optimize` (server-side filtering/pagination for the editor), then `/impeccable polish`.

## Detailed Findings by Severity

### P1

**[P1] Manager editor is English-only**
- Location: `src/components/editorSide/*` (every file: `editorNavBar`, `editorSideBar`, `editorItemElement`, `editorItemAddOverlay`, `editorItemEditOverlay`, `editorItemScroll`, `editorDeleteConfirmation`, `editorPageSelector`, `editorSwitchCategoryPromo`, `editorSideBarCategoryAdd`, `editorSideBarCategoryEdit`, `editorSideBarPromoAdd`, `editorSideBarPromoEdit`, `railForm`, `imageField`, `goldFields`, `editorOverlay`)
- Category: Implementation Integrity / Accessibility
- Impact: Every editor label is hard-coded English ("New piece", "Categories", "Promotions", "New category", "All pieces", "Uncategorized", "Name", "Category", "Stock", "Weight (grams)", "Purity", "Labor fee (฿)", "Photo", "Choose a photo", "Change photo", "Save piece", "Save changes", "Rows per page", "Page 1 of 1", "First page", "Previous page", "Next page", "Last page", "Keep it", "Delete", "Edit", "No promotions yet. Create one…", "No pieces here. Clear the filter…", "Delete this piece?", "will be removed from the catalog. There is no undo.", "Code, e.g. GOLD10", "Discount type", "Amount", "Cancel", "Back to the counter", "Toggle categories and promotions"). The cashier's i18n table already has matching keys (`allPieces`, `uncategorized`, `storeEditor`, `lockAndContinue`, etc.); the editor is the one surface that bypasses the system.
- Standard: PRODUCT.md ("Two languages, one layout. Thai and English must both fit without one being an afterthought"). WCAG 3.1.2 (language of parts) is met at the markup level; the gap is content.
- Recommendation: Add editor strings to `src/lib/i18n.ts`; route every editor label through `Bi` (or `th` where the design has only Thai). Native-speaker review is the constraint — do not add Thai without it.
- Suggested command: `/impeccable clarify` (after a native-speaker loop)

### P2

**[P2] Stale rate can be locked silently**
- Location: `src/pages/PaymentCalculation.tsx:22-34` (`handleLock`); the guard at line 23 only checks `!rate`, not `rate.stale`.
- Category: Implementation Integrity / Accessibility (counter-staff workflow)
- Impact: When the network is down and the last cached rate is older than `STALE_AFTER_MS` (5 min), the stamp shows the red "เก่า / Stale" marker (see `src/components/RateStamp.tsx:91`) and the stamp border in the popover goes dashed (`unavailable` state). The Lock button stays enabled. The cashier locks a rate the shop cannot defend if the market moves while the connection is dead.
- Recommendation: In `handleLock`, refuse to lock when `rate.stale` is true, and surface a stamp-tint note under the Lock button ("ใช้ราคาเก่าไม่ได้" once translated) with a "ลองใหม่ / Retry" call that calls `useGoldRateStatus().retry()`. Mirrors the `lockOld && rateMoved` review block at `src/components/PromptQR/PaymentPortal.tsx:48-52,88-97`.
- Suggested command: `/impeccable harden`

**[P2] Adding an item wipes the manager's active filter**
- Location: `src/pages/editorMenu.tsx:131-135` (`handleAddItem`); the same shape is in `editorSideBar.tsx:74` and `editorSideBarCategory.tsx:14-23`.
- Category: Implementation Integrity
- Impact: `setSearchParams({ page: '1' })` replaces all searchParams with `{ page: '1' }`. A manager who has filtered to one category and adds a new piece returns to "All pieces" on `page=1` and has to re-pick the category. The class of "reset to page 1" is harmless in the catalog (it doesn't paginate); in the editor it discards the active filter as a side effect.
- Recommendation: Replace the object form with the function form that merges: `setSearchParams((prev) => { prev.set("page", "1"); return prev; })`. Preserves `search` and `categories`.
- Suggested command: `/impeccable harden`

**[P2] Editor first render fetches the full inventory and filters / paginates in the browser**
- Location: `src/pages/editorMenu.tsx:34-55`; server side already supports query params (`server/src/controllers/ItemController.ts:18-67`).
- Category: Performance
- Impact: `useEffect` calls `getInventory()` with no params, returning every item. The `filteredItems` slice at lines 45-53 runs `title.toLowerCase().includes(...)` and `description.toLowerCase().includes(...)` over the full list on every render, then `currentItems = filteredItems.slice(...)` paginates client-side. At 13 seeded pieces the cost is invisible; at a few hundred real items the editor stalls on first open and stays slow as the manager types.
- Recommendation: Pass `{ search, categories }` to `getInventory` in the effect's deps, and push `page` / `row` to the server. The endpoint already accepts them; the editor is the only client that ignores them. Adds a debounce on the search box if the network is slow.
- Suggested command: `/impeccable optimize`

### P3

**[P3] Editor's add form sends a fake `id` and `updatedAt` to the server**
- Location: `src/components/editorSide/editorItemAddOverlay.tsx:32-45`; the server schema (`server/src/schemas/ItemSchemas.ts:4-14`) doesn't accept `id` so the value is silently dropped.
- Category: Implementation Integrity
- Impact: No bug, but the wire carries a value the server ignores; the next reader will wonder where the id comes from.
- Recommendation: Drop `id` and `updatedAt` from the `onSave` payload; the server creates the id and timestamps the row.
- Suggested command: `/impeccable distill`

**[P3] Editor's add-overlay pure-input strips a category row by `name` lookup**
- Location: `src/components/editorSide/editorItemAddOverlay.tsx:38` and `editorItemEditOverlay.tsx:39`: `categories.find((c) => c.name === category)?.id`.
- Category: Implementation Integrity
- Impact: Renaming a category while the overlay is open would let the cashier save a piece with no category. The form is short-lived so the window is small, but `categoryId` should be the form's source of truth (the `<datalist>` is a free-text field, not a select).
- Recommendation: Use `<select>` with a real "Uncategorized" option, or keep a `categoryId` state and only fall back to the name lookup on first render.
- Suggested command: `/impeccable polish`

**[P3] `PURITY` labels mix Thai and English inline, not via `Bi`**
- Location: `src/lib/gold.ts:3-9`.
- Category: Implementation Integrity
- Impact: A native Thai speaker reviewing copy has to edit `lib/gold.ts` (a number/locale file) rather than `i18n.ts` (the one place review happens). The labels work; the review ergonomics don't.
- Recommendation: Move the five purity labels into `S.purities96 / purityBullion / etc.`; the `value` stays in `lib/gold.ts`.
- Suggested command: `/impeccable polish` (rolled into the editor i18n pass)

**[P3] `PaymentItem` line and `editorItemElement` "labor" / "in stock" / "Sold out" inline English**
- Location: `src/components/editorSide/editorItemElement.tsx:30-32` ("labor", "in stock", "Sold out").
- Category: Implementation Integrity
- Impact: Two strings on the editor's most-seen row, not in `S`.
- Recommendation: Use `<Bi k="laborFee" thOnly />` and `<Bi k="stock" />` (key already exists for cashier). Same for the "Sold out" state.
- Suggested command: `/impeccable polish`

**[P3] Live-stamp `aria-live="polite"` is unconditional**
- Location: `src/components/RateStamp.tsx:86`.
- Category: Accessibility
- Impact: Screen readers announce the rate every 60s, even when the figure hasn't changed. A counter assistant with a screen reader running has to wait it out between sales.
- Recommendation: Drop `aria-live` on the rate figure; keep it on the "Stale" marker (which only appears once) and on the "เก่า" re-attempt.
- Suggested command: `/impeccable harden`

**[P3] Muted-ink contrast still not measured**
- Location: `src/index.css:23` (`--color-ink-muted: oklch(52% 0.018 70)`) used as the English companion colour in `Bi`, on card meta lines, on print sub-lines, and on the editor's per-page "Page 1 of 1".
- Category: Accessibility
- Impact: If `ink-muted` on `slip` or `paper` falls under 4.5:1, the English half of every label fails AA.
- Recommendation: Run a contrast pass on `ink-muted` against `slip` and `paper`; nudge the token darker if it fails.
- Suggested command: `/impeccable audit` (re-run with contrast tooling) then `/impeccable polish`

**[P3] `Receipt.tsx` and `PrintableReceipt.tsx` use `th()` / `en()` inline instead of `Bi`**
- Location: `src/components/PaymentCalculation/Receipt.tsx:91`; `src/components/PaymentCalculation/Printables/PrintableReceipt.tsx:12`.
- Category: Implementation Integrity
- Impact: The pattern works (Thai first, English 400 in `ink-muted`), but the helper exists. Three lines in `Receipt` and one helper in `PrintableReceipt` could collapse into `<Bi>`.
- Recommendation: Replace inline `th()/en()` pairs with `<Bi k="…" />` where the structure is just two spans. Keep the manual pair only when other content is interleaved (e.g. the discount line that also lists `promoCodes`).
- Suggested command: `/impeccable polish`

## Patterns & Systemic Issues

- **The editor is the back of the same counter, but it doesn't speak Thai.** The cashier flow is one product-specific system with a single i18n surface; the editor is an English-only island that shares the bar, the stamp, the slip and the Dialog but not the language. Closing this gap is the single biggest improvement available.
- **Guard the boundary, not the button.** Several findings (idempotency, lock-stale, add-resets-filter) are about money/state transitions that the UI already disables. The fix is one early return or one merged `setSearchParams` at the right function, not more disabled buttons.
- **Two filter shapes share one component.** `SearchBar` is used by both the catalog (which doesn't paginate) and the editor (which does). The `page=1` reset is a feature in the editor and a no-op in the catalog; the param is now a real argument to keep.

## Positive Findings

- All six 2026-10-06 P2 findings are closed in the cashier flow: idempotency, popover dismissal, sticky footer, phone search, lazy images, and server-side filtering.
- The rate stamp's two motion paths still respect `prefers-reduced-motion` (`src/index.css:81-83`); the strike is skipped before navigation in `PaymentCalculation.tsx:32-33`.
- One `Dialog` (focus trap, Escape, scrim click, focus return, bottom-sheet from 640px) serves buy, cash, PromptPay, editor overlays, and the delete confirmation.
- `Role` coverage: `aria-pressed` on rail rows, `aria-expanded` on the hamburger, `inert` on the collapsed rail, `role="combobox"` / `aria-activedescendant` on search, `role="alertdialog"` on the delete confirmation, `role="alert"` on error notes, `aria-busy` on the Lock and Confirm buttons while pending.
- Server recomputes every unit price from the locked rate and decrements stock in a transaction; the cashier cannot post a price.
- The `IntersectionObserver` on the receipt header (`src/components/PaymentCalculation/Receipt.tsx:36-46`) gates `sticky bottom-0` on the footer so the Lock button cannot sit on top of "ใบเสร็จ Receipt" on first view.
- Rate lock, promos, and cart survive a refresh; the payment page redirects to the bag if the lock is missing (`src/pages/SelectPaymentType.tsx:24`).
- `impeccable detect src` reports zero findings.
